# 字段映射动态化说明

## 功能概述

用户详情弹窗中的字段名称现在使用从后端 API（`GetEventFields`）返回的 `eventData` 进行动态映射，而不是使用硬编码的字段名称。

## 修改内容

### 修改前（硬编码方式）

```javascript
const formatFieldName = (key) => {
  const fieldNameMap = {
    name: '姓名',
    mobile: '手机号',
    email: '邮箱',
    regcode: '门票编号',
    ticketNumber: '门票编号',
    type: '类型',
    ticketType: '票种',
    printed: '打印状态',
    signed: '签到状态',
    printTime: '打印时间',
    signinTime: '签到时间',
    company: '单位',
    position: '职位',
    phone: '手机号'
  }
  return fieldNameMap[key] || key
}
```

**问题：**
- 字段映射固定，无法适应后端配置
- 不支持自定义字段（如 `cf_1753752905008`）
- 无法显示中英文双语字段名

### 修改后（动态映射方式）

```javascript
const formatFieldName = (key) => {
  // 第一层：优先使用eventData中的映射
  if (eventData.value && eventData.value[key]) {
    return eventData.value[key]
  }
  
  // 第二层：从fieldList中查找字段描述
  if (fieldList.value && fieldList.value.length > 0) {
    const field = fieldList.value.find(f => f.name === key)
    if (field && field.describe) {
      return field.describe
    }
  }
  
  // 第三层：使用默认映射
  const defaultFieldNameMap = {
    regcode: '门票编号',
    ticketNumber: '门票编号',
    type: '类型',
    ticketType: '票种',
    printed: '打印状态',
    signed: '签到状态',
    printTime: '打印时间',
    signinTime: '签到时间',
    position: '职位',
    phone: '手机号'
  }
  
  // 第四层：返回原始key
  return defaultFieldNameMap[key] || key
}
```

**优势：**
- ✅ 动态读取后端配置的字段映射
- ✅ 支持自定义字段的中文显示
- ✅ 支持中英文双语字段名
- ✅ 四层后备机制，确保所有字段都能正常显示
- ✅ 兼容性好，多重保障

### fieldList 数据示例

fieldList 是一个数组，包含字段的详细信息：

```json
[
  {
    "name": "name",
    "describe": "姓名"
  },
  {
    "name": "mobile",
    "describe": "手机号码"
  },
  {
    "name": "cf_1753752905008",
    "describe": "报到日期"
  },
  {
    "name": "cf_1753753045843",
    "describe": "性别"
  },
  {
    "name": "company",
    "describe": "公司名称"
  }

```

**字段说明：**
- `name`: 字段的键名（与用户数据中的 key 对应）
- `describe`: 字段的描述/显示名称

**注意：** fieldList 中的 describe 通常是简短的中文描述，而 eventData 中的值可能包含中英文双语。

## 字段映射逻辑（四层后备机制）

```
用户字段 key
    ↓
第一层：是否在 eventData 中？
    ├─ 是 → 返回 eventData[key]
    │        示例：name → "姓名 Name"
    │              mobile → "手机 Cell Phone"
    │              cf_1753752905008 → "日期"
    │
    └─ 否 ↓
第二层：是否在 fieldList 中？
    ├─ 是 → 返回 field.describe
    │        示例：customField → fieldList 中的 describe 值
    │              cf_1234567890 → fieldList 中的描述
    │
    └─ 否 ↓
第三层：是否在默认映射中？
    ├─ 是 → 返回默认映射值
    │        示例：regcode → "门票编号"
    │              printed → "打印状态"
    │
    └─ 否 ↓
第四层：返回原始 key
            示例：unknownField → "unknownField"
```

## 数据流程

```
1. 页面加载
    ↓
2. onMounted() 调用 getEventFields()
    ↓
3. API 返回 eventFields
    {
      success: true,
      data: { /* eventData 字段映射 */ },
      fieldList: [ /* 字段配置列表 */ ]
    }
    ↓
4. 保存到 eventData.value
    ↓
5. 用户点击姓名查看详情
    ↓
6. 弹窗显示用户信息
    ↓
7. formatFieldName(key) 格式化字段名
    - 查找 eventData.value[key]
    - 显示映射的中英文名称
```

## 优势

### 1. 灵活性
- 后端可以随时调整字段映射，无需修改前端代码
- 支持多语言配置（如中英文双语显示）

### 2. 扩展性
- 支持无限自定义字段
- 新增字段无需修改前端代码

### 3. 维护性
- 字段名称统一由后端配置管理
- 减少前后端协调成本

### 4. 用户体验
- 显示更加专业的中英文字段名
- 自定义字段也能有友好的显示名称

## 兼容性保障

### 四层后备机制

系统采用四层后备机制，确保在任何情况下字段都能正常显示：

```javascript
// 第一层：eventData 映射（最优先，通常包含中英文双语）
if (eventData.value && eventData.value[key]) {
  return eventData.value[key]  // 如：name → "姓名 Name"
}

// 第二层：fieldList 描述（新增，提供额外的字段描述）
if (fieldList.value && fieldList.value.length > 0) {
  const field = fieldList.value.find(f => f.name === key)
  if (field && field.describe) {
    return field.describe  // 如：name → "姓名"
  }
}

// 第三层：默认映射（兼容旧系统）
const defaultFieldNameMap = {
  regcode: '门票编号',
  ticketNumber: '门票编号',
  type: '类型',
  ticketType: '票种',
  printed: '打印状态',
  signed: '签到状态',
  printTime: '打印时间',
  signinTime: '签到时间',
  position: '职位',
  phone: '手机号'
}

// 第四层：原始 key（保底方案）
return defaultFieldNameMap[key] || key  // 如：unknownField → "unknownField"
```

### 降级策略优势

1. **优先级 1**：eventData 映射 - 最完整的显示（中英文双语）
2. **优先级 2**：fieldList 描述 - 后端配置的字段描述
3. **优先级 3**：默认映射 - 常用字段的固定映射
4. **优先级 4**：原始 key - 确保所有字段都能显示

这个四层机制确保了：
- ✅ 最优情况下显示完整的中英文信息
- ✅ eventData 缺失时仍能显示字段描述
- ✅ 新字段或特殊字段也能正常显示
- ✅ 极端情况下至少显示原始字段名

## 实际应用场景

### 场景一：国际会议
管理员查看外国参会者信息：
- 显示：`姓名 Name`、`手机 Cell Phone`、`邮箱 Email`
- 便于理解和沟通

### 场景二：自定义字段
会议有特殊字段（如住宿、考察线路）：
- `cf_1753753382900` → "酒店名称"
- `cf_1753775068086` → "科技文化考察线路（11月22日）"
- 清晰显示自定义信息

### 场景三：多类型参会者
不同类型参会者有不同字段：
- 展商：展商订房数、展商赠送房数
- 普通参会者：入场证件、身份证号
- 系统自动适配显示

## 注意事项

1. **eventData 必须加载**
   - 确保 `getEventFields()` 在页面加载时被调用
   - 检查 API 返回的 data 字段

2. **字段 key 的准确性**
   - 后端返回的字段 key 必须与 eventData 中的 key 一致
   - 大小写敏感

3. **性能考虑**
   - eventData 在内存中缓存，无需重复请求
   - formatFieldName 是轻量级函数，不影响性能
