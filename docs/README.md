## 📝 文档规范

### ⚠️ 文档生成原则（重要）

**最小化原则**: 仅在必要时生成文档，避免文档过度膨胀

#### ✅ 必须创建文档的情况
- **新增核心功能** - 影响用户使用流程的功能
- **架构级变更** - 影响项目结构或技术栈的变更
- **复杂Bug修复** - 需要详细记录原因和解决方案的重要Bug
- **API接口变更** - 新增或修改对外API接口
- **重大重构** - 影响多个模块的代码重构

#### ❌ 不需要创建文档的情况
- **代码微调** - 样式调整、文案修改、小的代码优化
- **简单Bug修复** - 一目了然的Bug修复（如拼写错误、简单逻辑错误）
- **依赖更新** - 常规的依赖包版本更新
- **代码重构** - 不影响功能的内部代码优化
- **UI微调** - 不改变功能的界面调整
- **注释更新** - 代码注释的补充和优化

#### 📌 文档更新策略
1. **优先更新现有文档**，而不是创建新文档
2. 小改动直接在代码注释中说明
3. 使用 Git commit message 记录常规变更
4. 只有重要变更才需要独立文档
5. 定期审查并删除过时或重复的文档

### 文档命名规范

1. **指南文档** - 使用描述性名称
   - 格式：`功能名称说明.md` 或 `功能描述.md`
   - 示例：`环境配置说明.md`、`START.md`

2. **功能文档** - 功能模块 + 说明
   - 格式：`功能模块名称说明.md`
   - 示例：`用户详情弹窗说明.md`

3. **快速参考** - 功能名称 + 快速参考
   - 格式：`功能名称-快速参考.md`
   - 示例：`打印功能重构-快速参考.md`

4. **Bug修复** - BUG修复 + 问题描述
   - 格式：`BUG修复-问题描述.md` 或 `修复总结-问题描述.md`
   - 示例：`BUG修复-分页参数.md`

5. **测试文档** - 功能名称 + 测试
   - 格式：`功能名称测试.md`
   - 示例：`门票编号自动查询测试.md`

### 文档编写规范

1. **使用中文** - 所有文档使用中文编写
2. **代码示例** - 包含实际可运行的代码示例
3. **图表说明** - 使用文字图表（ASCII art）或流程图
4. **版本信息** - 重要变更记录更新日期
5. **交叉引用** - 相关文档间相互链接
6. **保持更新** - 代码变更时同步更新文档

### 文档维护

**遵循最小化原则** - 仅为核心功能、重大变更、复杂Bug创建文档

- **新增核心功能** - 在 `features/` 下创建功能文档（仅限重要功能）
- **重大Bug修复** - 在 `bugfix/` 下记录修复过程（简单Bug只需commit message）
- **复杂测试场景** - 在 `testing/` 下添加测试文档（简单测试不需要）
- **快速参考** - 为复杂功能创建快速参考卡片
- **更新索引** - 新增文档后更新本 README
- **定期清理** - 删除过时、重复或不必要的文档
